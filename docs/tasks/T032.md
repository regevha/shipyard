# T032 hand-off: release-service version cap and event deadline (wave 2 follow-up F1)

## Done
- Q-40 (#170): `artifact.version` is 1 to 2^63-1 (`MAX_VERSION` in `app/models.py`, `le=`). Above that is 422
  `validation_failed`, location `body.artifact.version`, nothing stored, no event. 2^63-1 comes back exactly from the
  201, GET, decision, promote and in both event payloads. The column is `BigInteger` (`app/repos/tables.py`); `DATA_MODEL.md`
  updated. **No migration**: the stack starts with a wiped data dir (`create_all`, throw-away data). A stale
  `release_service.db` with the old text column would need deleting.
- Q-42 (#171): `app/core/events.py` is an async sender: one `httpx.AsyncClient` per app, closed in the lifespan; each
  event its own `asyncio` task; the handlers' background task is an `async def` that only schedules the task and returns
  (never awaited, never on the thread pool); 5 s total deadline, attempt timeout `min(2 s, time left)` (enforced with
  `asyncio.timeout`, so it is a total, not per phase), waits 0.5 s then 1 s, no attempt or wait past the deadline, same
  `event_id`, retry only on network error, timeout or 5xx; at most 1000 pending (one more dropped and logged); lifespan
  exit cancels pending sends and waits at most 1 s. Scheduling is still after the commit.
- Injectable: `Settings.event_deadline_seconds`, `event_timeout_seconds`, `event_backoff_seconds`, `event_pending_cap`;
  `create_app(settings, transport, sleep)` (async `sleep`); hooks `EventSender.pending()` and `EventSender.wait_idle()`.
  Test conftest has `Fakes.sleep` (async, records) and `settle(client)`; `make_release`/`decide` settle automatically.
