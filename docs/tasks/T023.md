# T023 hand-off

Dashboard backend per `contracts/api-dashboard.yml`. Read-only (Q-23, Q-32): the only write endpoint is
`POST /events`; the dashboard calls no other service.

## Endpoints
- `POST /events`: 202, empty body; 422 `validation_failed` for anything but exactly one valid event of
  `contracts/events.yml` (unknown type, wrong source, unknown field, trailing newline in any string, invalid
  JSON, and the build.finished/step state tables incl. `failed_step` naming the one failed step, steps before it
  passed, after it skipped). A repeated `event_id` is 202 and changes nothing.
- `GET /builds?status=running|passed|failed&limit&offset`, `GET /artifacts`, `GET /releases` (`limit` 1-200
  default 50, `offset` default 0), each `{items, limit, offset}`.
- `GET /` serves `static/index.html` (text/html); `/static/*` is `StaticFiles`. Nothing is mounted at `/`, so
  GET /events is 405 (Allow: POST), POST /nope is 404, POST /static/x is 405 (Allow: GET, HEAD).
  Static tests check status, content type and envelopes only, so T027 can replace the page.

## Seeding events with curl (T027, T028)
Start: `SHIPYARD_SLOT=<n> scripts/dev/start-stack.sh` (dashboard port 18003 + 10 x slot). Then:
```
curl -s -X POST localhost:$PORT/events -H 'content-type: application/json' -d '{
 "event_id":"0b7f3a52-9c1d-4e8a-8f43-2d6c1b9e7a01","type":"build.started","schema_version":1,
 "occurred_at":"2026-11-25T10:00:00Z","source":"pipeline-runner",
 "data":{"build_id":"5d0c6f1e-2b7a-4c39-9e8d-41a2f6b3c701","pipeline_name":"shipyard-api"}}'
```
Every event needs a fresh `event_id` (UUID), `schema_version` 1 and a `Z` timestamp. Other bodies: the examples
under `POST /events` in the contract (build.finished failed, artifact.uploaded, release.requested,
release.decided). Poll `GET /builds`, `/artifacts`, `/releases` after the 202 (the write is committed before the
202, verified with a real server: 500 POST-then-GET loops, 0 misses).

## Ordering (read this before writing UI or stack tests)
- Builds and releases sort by the latest `occurred_at` among their events, descending; artifacts by
  `uploaded_at`. Equal timestamps tie-break by id ascending, so seeding many items with the same
  `occurred_at` gives an arbitrary but stable order: use distinct timestamps in tests.
- A finished build moves up when its finish event is newer. An out-of-order older event never moves an item up.
- A field already set is never overwritten by a later event (first accepted wins).
- `/artifacts` lists every uploaded artifact, also one whose build failed (#131 option a).
