# T012 hand-off

Built: the six contract files under `contracts/` and new open questions Q-28 to Q-32 in `docs/OPEN_QUESTIONS.md`.

Shape:
- `events.yml`: five event types, `build.started`, `build.finished` (`data.outcome` passed/failed), `artifact.uploaded`,
  `release.requested`, `release.decided` (`data.decision` approved/rejected) (Q-13). Each one is
  `allOf: [Envelope, {type/source/schema_version consts, data: <closed payload>}]` + `unevaluatedProperties: false`.
  Envelope `{event_id, type, schema_version, occurred_at, source, data}` (Q-12). The root `oneOf` is "any event".
- Shared value schemas live in `events.yml#/$defs` and are the only definition of each concept: `BuildId`,
  `ReleaseId`, `EventId`, `Timestamp` (UTC, `Z`), `PipelineName`, `StepName`, `StepStatus`, `StepResult`,
  `BuildOutcome`, `ArtifactName`, `ArtifactVersion`, `Checksum`, `ArtifactRef`, `Artifact`, `Decision`, `Actor`.
  The api files `$ref` them; `RunStatus` (runner) and `ReleaseStatus` (release-service) are reused by the dashboard.
- `errors.yml`: `ErrorEnvelope {error: {code, message, details?}}`; codes and statuses in `x-status-codes`.
- Endpoints: runner `POST /runs`, `GET /runs/{build_id}`; artifact-store `POST /artifacts/{name}?build_id=`,
  `GET /artifacts/{name}/versions/{version}` (checksum header `X-Checksum-SHA256`); release-service `POST /releases`,
  `GET /releases/{release_id}`, `POST /releases/{release_id}/decision`, `POST /releases/{release_id}/promote`;
  dashboard `POST /events` (body `$ref: events.yml#`, lead decision #79), `GET /builds`, `GET /artifacts`,
  `GET /releases`. Who calls whom: table in `contracts/api-dashboard.yml` `info.description`.
