# T028 hand-off: stack tests, CI `stack` job, docs/DEMO.md

## What exists
- `stack-tests/tests/` (no `__init__.py`; pytest puts `tests/` on `sys.path`):
  - `conftest.py`: session fixture `stack` runs `scripts/dev/start-stack.sh` for `SHIPYARD_SLOT`
    (required; a missing or non-numeric slot is an error, never defaulted) and `stop-stack.sh` at the end.
    URLs and data dir come from `scripts/dev/ports.sh`. `PIPELINE_RUNNER_STEP_SECONDS` defaults to `0.05`
    (the scripts pass the environment on; set it yourself to override). Marker `stops_artifact_store`: such
    tests are sorted after all others, whatever order they are named in on the command line.
  - `contract.py`: `Contracts.check(service, httpx.Response)` looks up the operation by method, path
    template and status in `contracts/api-<service>.yml`, fails on an undocumented status, a wrong
    content-type, a missing required header (`X-Checksum-SHA256` on downloads) or a body that does not
    validate (Draft 2020-12, every `$ref` inlined from disk incl. `events.yml`/`errors.yml`). Of the
    formats only `uuid` is checked; `date-time` is not enforced (rfc3339-validator is not in the lock),
    so timestamps are checked only by the contract's `Z$` pattern and its no-line-break `not`.
    `GET /` and `/static/app.js` on the dashboard are not in a contract and are skipped.
  - `stack.py`: `Stack.call(service, method, path, ...)` (every response checked), `start_run`, `wait_run`,
    `dashboard_items` (pages of 200), `wait_dashboard`, `poll`.
  - `test_stack_flow.py`: the seven tests named in the spec, plus
    `test_contract_checker_rejects_what_the_contract_forbids` (no stack needed; proves the checker is not
    vacuous). `test_every_response_validates_against_contract_schema` also asserts that every operation of
    the four contracts was called at least once.
  - `test_stack_concurrency.py`: 100 `POST /runs` at once (asyncio), every 5th with a `fail` step; every run
    reaches its final state, the dashboard lists each build exactly once with the runner's status and steps,
    artifacts are exactly one per passed build with versions 1..80, checksums spot-checked.
  - `test_stack_upload_failure.py`: SIGTERM to artifact-store's pid, then a passing pipeline is `failed`,
    `failed_step` null, `failure_reason` `artifact upload failed`, also on the dashboard, no retry.
- `stack-tests/pyproject.toml`: only `[tool.ruff.lint.isort] known-first-party = ["contract", "stack"]`
  added (no dependency change; `uv.lock` untouched).
- `.github/workflows/ci.yml`: job `stack` (same pinned checkout and setup-uv 0.13.10 as `service`,
  `permissions: contents: read`, `SHIPYARD_SLOT=0`), which runs `uv sync --locked` in the four services and
  stack-tests before anything starts the stack (#154), then ruff check, ruff format --check, mypy and
  `pytest -v --durations=10`; prints the service logs on failure. `stack` is in `ci-ok`'s needs. Other jobs
  unchanged.
- `docs/DEMO.md`: `## Run it`, `## Walkthrough` (one `sh` block, runs under `bash -euo pipefail` for any
  `SHIPYARD_SLOT`, waits 6 s at each "look at the browser" line, `DEMO_PAUSE=0` skips them; about 37 s with
  pauses), `## Known limitations`.

## Durations (slot 6, this machine)
Full suite about 29-31 s: concurrency 15 s, stack start 2.3 s, upload failure 2 s, stop 5.6 s, the rest
under 1.1 s each.

## Not tested (on purpose)
- 413 on artifact-store (needs a 100 MiB body; covered by T025's unit and real-server tests).
- Versions above 2^63-1 on the dashboard (#170, deferred; listed in DEMO.md).
