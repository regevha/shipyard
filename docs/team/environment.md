## Decided by the user
- Python + FastAPI for every service.
- Services talk over plain HTTP at first; a real event queue comes later.
- One repo, one folder per service: `services/<name>/`.
- Planned services: `pipeline-runner`, `artifact-store`, `release-service`, `dashboard`.

## Proposed by the lead (working assumptions, not user decisions; the approved wave 2 setup below builds on them)
- Each service owns its own data, with no shared database, and a service uses another service only through its contract.
- Contracts avoid assuming a call is synchronous, so the queue can replace calls later.
- Contracts (Q-01, resolved by the user brief; follow-up #36): `contracts/api-<service>.yml` per service plus `contracts/events.yml` and `contracts/errors.yml` (ids, statuses, the error envelope and who calls whom), owned by the architect and changed only through the lead. There is no `docs/contracts/` folder and no per-service data-model contract; each service documents its tables in `services/<s>/DATA_MODEL.md` (see the Contracts row in "Wave 2 setup (T019, approved)").
- `e2e/` belongs to `e2e-tester` only (browser flows through the dashboard). `tester`'s stack-level HTTP tests that start several services live in `stack-tests/` at the repo root (approved wave 2 setup), never in `e2e/`.

## Layout map for the synced team files
The synced files (`CLAUDE.md`, `docs/team/lead.md`, `.claude/agents/`, `docs/tasks/README.md`) were written for one `server/` + `web/` app. In Shipyard read their paths like this:
- `server/` means `services/<service>/` for the service the task names, with the same inner shape: `app/` (data access in `app/repos/`), `db/` if the service has a database, `tests/`.
- `web/` means the dashboard's UI code: `services/dashboard/static/` (plain HTML + JavaScript, no build step, Q-02), owned by `frontend-dev`. `backend-dev` owns the dashboard's `app/` and `tests/`; neither edits the other's folder.
- `docs/API.md` means `contracts/api-<service>.yml`; the shared contract is `contracts/events.yml` and `contracts/errors.yml` (Q-01, #36). All of `contracts/**` is frozen during a wave (except for a Blocking defect, as in `lead.md`) and changes only through the lead. `project-manager`, `chore` and `product-manager` treat every file under `contracts/` as a contract. `docs/DATA_MODEL.md` means `services/<s>/DATA_MODEL.md`, owned by `backend-dev` in wave 2; it is documentation, not a contract, and is not frozen.
- The "Team or direct" module list in `lead.md` counts modules per service (`services/<s>/app/<package>`, `services/<s>/db/`, `services/<s>/tests/`), and any change that touches two services' code or contracts counts as large.
- Lockfiles: one per service (`services/<s>/uv.lock`, and the UI's lockfile if it has one). The "one agent per side" rule becomes one agent per service.
- In `docs/tasks/Tnn.yml`, `files_touched` and `read_first` use the real paths, for example `services/pipeline-runner/app/**` and `contracts/api-pipeline-runner.yml#/paths/~1runs`. CI checks those, not this map.

## Commands
Per service, from `services/<service>/`: `uv run pytest`, `uv run ruff check .`, `uv run ruff format --check .`, and `uv run mypy`, which needs `[tool.mypy] files = [...]` in that service's `pyproject.toml` (without it mypy exits with an error). Each service's `pyproject.toml` and the stack-level start command are set in "Wave 2 setup (T019, approved)" below and are created by the wave 2 scaffold task (T021). From the repo root: `scripts/dev/start-stack.sh` and `scripts/dev/stop-stack.sh` (with `SHIPYARD_SLOT` set to your slot). Export `SHIPYARD_SLOT` and any database URL variables on every shell call (the environment does not persist).

## Worktrees, ports and databases
- Work in your own git worktree on the branch named in your task spec. Commit locally; never push.
- Ports: the lead assigns each agent a slot. A slot has one port per service, in the service order above. The base and formula are in "Wave 2 setup (T019, approved)" below: port = 18000 + 10 x slot + service index (`scripts/dev/ports.sh` computes them). Never use another port number.
- Databases: name them `shipyard_<task>_<agent>_<service>` in lowercase, with every hyphen written as an underscore (for example `shipyard_t012_backend_dev_pipeline_runner`), one per service you start. State in your report that ports and databases were cleaned up. This pattern replaces the `<project>_<task>_<agent>` names in the synced agent files (for example `e2e-tester`'s `<project>_<task>_e2e`). In wave 2 these names are not used: SQLite files under the slot's data dir replace them (SQLite file row below); clean up by stopping the stack and deleting `/tmp/shipyard/slot<N>`.
- Never run two agents at once that edit files the other one tests or builds on. A contract change request goes to the lead with the list of consuming services and their tests.
- Put scratch files (downloaded tools, tarballs) in `/tmp`, never in the repo.
