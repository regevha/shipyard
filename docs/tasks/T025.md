# T025 hand-off

artifact-store (`services/artifact-store/`), built to `contracts/api-artifact-store.yml`.

## Endpoints
- `POST /artifacts/{name}?build_id=<uuid>`: raw `application/octet-stream` body; optional header
  `X-Checksum-SHA256`. 201 answers the Artifact (`name`, `version`, `checksum`, `size_bytes`, `build_id` as sent,
  `uploaded_at`). 413 `payload_too_large`, 422 `validation_failed` / `checksum_mismatch`. Order: 413, then 422
  validation (path, query, header), then 422 checksum_mismatch (nothing stored, version not consumed).
- `GET /artifacts/{name}/versions/{version}`: the bytes with `X-Checksum-SHA256`; 404 `not_found`; 422 for a bad
  name or a version below 1 / not an integer. A version above 2^63-1 is 404 (it cannot exist). The 200 is a plain streamed response with Content-Length (the file is opened inside an async generator, so a cancelled stream closes it); `Range` is ignored (always 200, whole body, no 206). A row whose blob file is gone answers 500 `internal_error`.
- After the 201 is committed, a background task sends `artifact.uploaded` to `$DASHBOARD_URL/events` (3 attempts,
  2 s timeout, 0.5 s then 1 s wait, same `event_id` on retries, retry on network error, timeout or 5xx, never
  raises into the upload). `occurred_at` equals `data.uploaded_at`.

## Environment variables
`SHIPYARD_SLOT` (default 0), `SHIPYARD_DATA_DIR` (default `/tmp/shipyard/slot<slot>`),
`ARTIFACT_STORE_DATABASE_URL` (default `sqlite:///<data dir>/artifact_store.db`), `DASHBOARD_URL` (default
`http://127.0.0.1:<18000 + 10 x slot + 3>`). Read in `app/core/config.py`.

## Where blobs live
`$SHIPYARD_DATA_DIR/artifact_store_blobs/<random hex>`, written by `app/repos/blobs.py` (file first, then the row
is committed, then the 201). See `services/artifact-store/DATA_MODEL.md`.

## How the 413 is detected
`app/routers/artifacts.py` `read_upload`, a dependency taking only `Request`, so it runs before path, query and
header validation. A `Content-Length` over 104857600 is refused at once; otherwise the body is read with
`request.stream()` chunk by chunk, hashing as it goes and spooling to a temp file (in memory only up to 1 MiB),
and the read stops with `ApiError(413)` as soon as the running size passes the limit. A body without
Content-Length is therefore never read past limit + one chunk. `await request.body()` is not used. Exactly
104857600 bytes is accepted. Proven by `test_limit_is_104857600_bytes`,
`test_body_reader_stops_as_soon_as_limit_is_passed` and a real-server chunked upload (413).

## Layout and decisions
- `app/main.py` `create_app(settings, sender)` builds the app (module-level `app = create_app()` reads env;
  engine, tables and blob dir are created in the lifespan at startup). Tests pass a tmp data dir, `sqlite://` and an
  `EventSender` with `httpx.MockTransport` (fake dashboard in `tests/conftest.py`).
- Versions: `max(version) + 1` per name inside the commit, unique `(name, version)` with retry on conflict.
- `build_id` is a string validated as a UUID and stored as sent (no case change). Uploads are accepted whatever
  the build's later outcome (#131, option a).
- No new package; `pyproject.toml` and `uv.lock` are unchanged (the lock already held every dependency).
