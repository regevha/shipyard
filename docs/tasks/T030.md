# T030 hand-off: dashboard version cap and internal-error build.finished

Implements the T029 contract changes in the dashboard (no contract change here).

## Changes
- `app/models.py`: `Version` has `le=9223372036854775807` (Q-40, #170), so an artifact version above 2^63-1 in
  artifact.uploaded, release.requested or release.decided is 422 `validation_failed` (no more SQLite overflow 500);
  nothing is stored. 2^63-1 is accepted and read back exactly. `FailureReason` gets `internal error` (Q-41, #167).
  `BuildFinishedData` state table: with `internal error` the steps must be InterruptedRunSteps (passed, failed or
  skipped, at most one failed, order passed then failed then skipped) and `failed_step` null; the upload reason
  still requires every step passed; outcome passed with any reason is 422.
- `app/repos/views.py`: the stored reason is returned as received (was always "artifact upload failed").
- `tests/test_dashboard_followups.py`: the five named tests; responses are validated against the BuildPage,
  ArtifactPage and ReleasePage contract schemas.
- No column changed, so `DATA_MODEL.md` is unchanged. `static/`, `pyproject.toml`, `uv.lock`, T022 copies untouched.

## Notes
- The 422 `details` location for a too-large version is `body.artifact.uploaded.data.version` (and
  `body.release.requested.data.artifact.version`): the discriminator tag is part of the path, as for every other
  event field today. Tests match the tail `data.version` / `data.artifact.version`.

## Open questions
- None. (Rare cases not covered, per the project owner's rule: running a stored row with a reason outside the two
  known values is not possible through intake, so the view maps unknown reasons to "artifact upload failed".)
