# T033 hand-off

pipeline-runner, wave 2 follow-up F2: an unexpected error fails the run with `internal error` (Q-41, #167), the
failed step, the skipped steps and the final state are one commit, and build.started and build.finished go through
the 5 s deadline sender (Q-42, #171). All three are the project owner's decisions of 2026-11-27. No contract change,
no new package (`pyproject.toml` and `uv.lock` untouched), the T022 copies untouched.

## Q-41: internal error
- `Runner.execute` catches any exception from `_execute`, logs it and calls `RunRepo.fail_internal(build_id, now)`.
  That repo method works in a fresh session and one commit: the running step is failed with `finished_at` now,
  pending steps are skipped, passed steps are kept, the run is failed with `finished_at` now, `failed_step` null and
  `failure_reason` `internal error`. It returns the run, which is sent as build.finished (the same fields).
- A run whose final state is already committed is kept: `fail_internal` returns None when the run is not `running`,
  and no second build.finished is sent.
- The upload maps only `httpx.HTTPError` (a network error or a timeout) and a non-201 answer to
  `artifact upload failed`; any other exception there is now an internal error (this changes T024).
- `FailureReason` in `app/models.py` has the second value; `DATA_MODEL.md` names it (no column change).
- The mark-failed write itself failing is out of scope (the project owner: rare cases are ignored until the end of
  wave 3); it is only caught and logged so `execute` never raises. No retry, no test, no note beyond this line.

## One transaction
- `RunRepo.fail_step` replaces `set_step(failed)` + `skip_steps_from` + `finish(failed)`: one commit. `skip_steps_from`
  is removed (unused). The upload-ended final state is still its own commit after the last step passed: the contract's
  running row allows a running run with every step passed, and Q-36 requires the upload to happen in that state.
- `test_every_intermediate_run_state_matches_contract` listens to SQLAlchemy `after_commit`, reads the run through a
  second connection after every committed write and validates each snapshot against the contract's `Run`, for a
  passed run, a failed-step run, an upload-failed run and an internal-error run.

## Q-42: event sender (`app/core/events.py`)
- Same design as artifact-store's: `build_started` and `build_finished` (called from the runner's worker thread) count
  the event (cap 1000, one more dropped and logged) and hand it to the loop with `call_soon_threadsafe`; each is its
  own `asyncio` task; deadline 5 s from the hand-over; attempt timeout `min(2 s, time left)` via `asyncio.timeout`;
  waits 0.5 s then 1 s; no attempt or wait starts past the deadline; same `event_id` on every attempt; retry only on
  `httpx.TransportError`, a timeout or a 5xx; one `httpx.AsyncClient` per app, closed in the lifespan; `close()`
  cancels pending sends within 1 s. Hooks: `pending()`, `wait_idle()`; injectable `deadline`, `attempt_timeout`,
  `waits`, `max_pending`, `sleep`, `clock`, `transport`.
- `create_app(settings, transport, sleep, events)`: `transport` is the upload's, `sleep` the simulated step delay,
  `events` an optional sender (tests). `Settings.event_timeout_seconds` and `event_backoff_seconds` are removed
  (the sender's constants replace them).
- Simulated steps and the upload still run in the worker thread (wave 3, Q-42 follow-up); not changed.
- Existing tests: `tests/conftest.py` builds the sender with the fake transport and a recording async sleep, and has
  `settle(client)`; `test_runner_execution.py` waits for the sender to be idle and no longer assumes the started event
  arrives before the upload (they travel on separate tasks; the upload still precedes build.finished) or that the
  two events' retries are sequential (assertions group by `event_id`). The old "stays running, only logged" test is
  replaced by `tests/test_runner_internal_error.py`. `tests/test_main.py` points DASHBOARD_URL and ARTIFACT_STORE_URL
  at a closed port and uses step seconds 0, so it never posts to a real `$DASHBOARD_URL`.

## Measured
- Hanging-dashboard scenario (80 concurrent POST /runs, dashboard accepts and never answers, then one GET timed):
  on the unfixed code (main 7afea81, the same scenario in a scratch copy under /tmp) unfixed: 13.0 s and 13.4 s in two
  runs; with this change the test asserts under 1.0 s while `pending() >= 1` both before and after the timed GET.
- Live probe, slot 2, real dashboard and artifact-store from this tree, with a scratch wrapper (under /tmp) that made
  the upload raise for pipelines named `crash-*`: the crashed run ended failed with `failure_reason` internal error
  (step passed, failed_step null) and the dashboard's `/builds` showed it; 150 parallel runs left none running
  (80 passed, 40 internal error, 30 failed at a step), and the dashboard showed the same counts.

## Mutation proofs (scratch copy under /tmp, each fails a test)
- `handed + 1e9` as the deadline: `test_q42_event_dropped_at_deadline` fails.
- attempt timeout without `min(.., left)`: `test_q42_event_dropped_at_deadline` fails (1.3 s instead of 1.0 s).
- the wait-past-the-deadline guard removed: `test_q42_event_dropped_at_deadline` fails.
- `fail_step` split into several commits: `test_every_intermediate_run_state_matches_contract[failed-step]` fails
  (a running run with a failed step).
