# T026 hand-off: release-service

Implements `contracts/api-release-service.yml`. Code in `services/release-service/app/` (`routers/releases.py`,
`repos/releases.py`, `repos/engine.py`, `core/events.py`, `core/config.py`, `models.py`); tables in
`services/release-service/DATA_MODEL.md`. Port `18000 + 10 x slot + 2`; env `RELEASE_SERVICE_DATABASE_URL`, `DASHBOARD_URL`.

## Behaviour
- `POST /releases` 201 pending; `requested_by` free non-empty string (Q-30); artifact not checked, artifact-store never called (Q-16).
- `POST /releases/{id}/decision`: one final decision (409 `release_already_decided`); `decision` is exactly `approved` or `rejected`.
- `POST /releases/{id}/promote`: 409 `release_not_approved` unless approved; second promote 200, unchanged, first `promoted_at` (Q-31); no event (Q-14).
- Precedence on decision: 422 path, 404, 422 body (also for invalid JSON), 409. Done by a dependency that loads the release before the body is validated.
- Request bodies are strict (no `"3"`/`true` for an integer, no number for a string), unknown fields are 422.
- Events `release.requested` / `release.decided` go out from a background task after the commit; 3 attempts, then dropped.
- A version above 2^63-1 is accepted (contract sets no maximum) and stored as text.

## curl (slot 0 ports; replace 18002 with your slot's release-service port)
```
R=http://127.0.0.1:18002
ID=$(curl -s -XPOST $R/releases -H 'content-type: application/json' \
  -d '{"artifact":{"name":"shipyard-api","version":3},"requested_by":"sam"}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["release_id"])')
curl -s -XPOST $R/releases/$ID/promote          # 409 release_not_approved
curl -s -XPOST $R/releases/$ID/decision -H 'content-type: application/json' \
  -d '{"decision":"approved","decided_by":"dana"}'   # 200 status approved
curl -s -XPOST $R/releases/$ID/promote          # 200, promoted_at set; repeat: same body
curl -s -XPOST $R/releases/$ID/decision -H 'content-type: application/json' \
  -d '{"decision":"rejected","decided_by":"lee"}'    # 409 release_already_decided
curl -s $R/releases/$ID
```

## Notes for the lead
- Dashboard defect found by the live probe (not in my files): `POST /events` answers 500 (`OverflowError: Python int too large to convert to SQLite INTEGER`) for a `release.requested` whose `artifact.version` is above 2^63-1; release-service then drops the event after 3 attempts. Either T023 stores versions safely, or the contract caps versions.
- No request-body size cap: the contract lists no 413 for this service, so adding one would differ from it.
