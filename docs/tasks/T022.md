# T022 hand-off

Shared modules, written once under `shared/` and copied byte-identical to the four services
(`scripts/ci/check_shared_copy.py`). Never edit a copy; change `shared/...` and re-copy
(`cp shared/errors.py services/<s>/app/errors.py`, `shared/openapi_conformance.py` to
`services/<s>/tests/openapi_conformance.py`, the two `shared/tests/test_*.py` to
`services/<s>/tests/test_shared_*.py`). Format with a service's ruff config
(`uv run ruff format --config pyproject.toml ../../shared` from a service folder).

## Public functions

`app/errors.py`
- `ApiError(status: int, code: ErrorCode, message: str, details: Sequence[ErrorDetail] | None = None)`:
  raises `ValueError` at construction when `(status, code)` is not an `errors.yml` pair (`ALLOWED_PAIRS`).
- `ErrorDetail(location, message)`, `ErrorBody`, `ErrorEnvelope`, `ErrorCode` (Literal), `ALLOWED_PAIRS`.
- `install(app: FastAPI) -> None`: registers the handlers and replaces `app.openapi`.
- Behaviour: validation error (also invalid JSON, location `body`) is 422 `validation_failed` with
  `details` (max 100), locations `body.steps.0.name`, `path.x`, `query.x`, `header.x-checksum-sha256`;
  Starlette 404/405 (Allow kept, all `exc.headers` passed)/413 get their code; other 4xx is 422
  `validation_failed`; 5xx and unhandled exceptions are 500 `internal_error` with a fixed message (no
  internals). A string `HTTPException.detail` is used as message for 4xx only; prefer `ApiError`.
- OpenAPI: `HTTPValidationError`/`ValidationError` removed; components `ErrorEnvelope`, `ErrorDetail`,
  `ErrorCode` added (written by hand in the module, `details` not nullable, same as the contract); every
  operation gets 422 and 500; every 4xx/5xx a route declares in `responses=` (and 4XX/5XX keys) keeps its
  description and gets the envelope as its only content. 404 for unknown paths and 405 with `Allow` keep
  working with `StaticFiles` mounted at `/static` and a `GET /` route (tested).

`tests/openapi_conformance.py`
- `differences(app_spec: dict[str, Any], contract_path: str | Path) -> list[str]`
- `schema_validator(contract_path: str | Path, pointer: str) -> Draft202012Validator` (pointer
  `"#/components/schemas/Run"` or `"events.yml#/$defs/StepResult"`; formats checked; `$ref`s inlined)
- `find_contract(name: str) -> Path` (walks up from the file to the first dir holding `contracts/errors.yml`)

## A service wires it like this

In `app/main.py` (service task): `from app.errors import install`, then `install(app)` after the routers
are included. `tests/test_contract_conformance.py`:

```python
from app.main import app
from openapi_conformance import differences, find_contract

def test_openapi_conforms_to_contract() -> None:
    assert differences(app.openapi(), find_contract("api-<service>.yml")) == []
```
and for real responses: `schema_validator(find_contract("api-<service>.yml"), "#/components/schemas/Run").validate(body)`.

## Normalisation rules (what `differences` compares)
- Compared: set of (method, path); per operation the response status codes, request/response media types,
  parameters as (in, name, required) (header names case-insensitive; path-level parameters merged), and,
  for JSON media types (`application/json`, `+json`) when the contract gives a schema, every property path
  with required flag and JSON types, plus every contract example (media-type `example`/`examples` and
  top-level schema `examples`) validated against the app's schema. Not compared: descriptions, titles,
  `additionalProperties`, formats, patterns, enums, bounds, parameter schemas, `requestBody.required`,
  response headers, non-JSON schemas.
- Every `$ref` (local and cross-file, read from disk) is inlined; sibling keywords next to `$ref` become an
  `allOf`; recursive refs become "anything".
- Paths: `a.b`, array items `a[]`, map values `a.*`; root is "(whole body)".
- `allOf`: union of properties and types, union of `required`. `anyOf`/`oneOf`: union of properties and
  types; a property is required only if every non-null branch requires it. So contract state tables
  (anyOf of constraint branches) fold into the base properties, and the app need not encode them; they are
  enforced by `schema_validator` in service tests.
- A missing `type` is inferred from `const`/`enum`. If the contract states no type for a property, the type
  is not compared (the app side must still match when the contract states one). `integer` != `number`.
- Pydantic's `anyOf [X, null]` equals the contract's `anyOf`/`type: [X, "null"]`: both give types `{X, null}`.
  A pydantic field with a default is not required in request schemas: give required-but-nullable contract
  fields no default.

## For T025 (artifact-store)
- Raw body: declare it with `openapi_extra`, and read `await request.body()` or the stream:
  `@router.post("/artifacts/{name}", status_code=201, response_model=Artifact, responses={413: {"description": "..."}},
  openapi_extra={"requestBody": {"required": True, "content": {"application/octet-stream": {"schema": {"type": "string", "format": "binary"}}}}})`.
  Non-JSON media types are compared by name only (the contract's `application/octet-stream: {}`).
- Download: `response_class=Response, responses={200: {"description": "...", "content": {"application/octet-stream": {}}}, 404: {...}}`
  and return `Response(data, media_type="application/octet-stream", headers={"X-Checksum-SHA256": ...})`.
- Header: `Annotated[str | None, Header(alias="X-Checksum-SHA256")] = None`.
- 413 before parameter validation: put the size check in a dependency listed in `dependencies=[Depends(check_size)]`
  that takes only `Request` and raises `ApiError(413, "payload_too_large", ...)`; dependencies run before the
  endpoint's own path/query/header validation. A body without Content-Length must be size-checked while
  reading (T025's job).
- I checked a stub with exactly these declarations against the real `contracts/api-artifact-store.yml`
  (scratch only, not committed): `differences()` returned `[]`, an oversized upload with an invalid name
  answered 413 and a small one 422.
